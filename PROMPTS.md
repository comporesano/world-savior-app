# PROMPTS.md — дневник промптов

Хронология запросов к ИИ-агенту и того, что было сделано по каждому из них.
Ключевой артефакт проекта: показывает, как из исходного задания получилось
работающее приложение.

---

## 0. Исходный промпт пользователя

> Смотри README.md и напили какой-нибудь неплохой проектик с одним из типов,
> КРОМЕ «Решение с элементами машинного обучения», «Информационная система для
> организации», «Мобильное приложение». Все остальное выбери тему придумай
> обоснование и напили хорошенький проект современный

Контекст: README.md содержит задание с шестью типами проектов и примерной
структурой (README, PROMPTS.md, REFLECTION.md, `src/`, `tests/`, `docs/` со
скриншотами и demo.mp4, `.agent/`).

---

## 1. Выбор типа и темы

**Запрос агенту:** «Из доступных типов — сервис визуализации данных,
клиент-серверное приложение с REST API и авторизацией, инструмент
автоматизации — выбери один, придумай тему и обоснование».

**Решение:** тип «Клиент-серверное приложение с REST API и авторизацией»,
тема **EcoSavior — платформа экологических инициатив** (название репозитория
world-savior-app прямо ложится на тему «спасения планеты»).

**Обоснование:** многопользовательский сценарий требует сервера и БД;
авторизация критична для честного учёта эко-баллов; REST API расширяем
(мобильные клиенты, интеграции); геймификация волонтёрства — актуальная
практика.

---

## 2. Уточнение стека у пользователя

**Запрос агенту:** «Сначала был построен вариант на Node.js (Express +
React). Пользователь прервал работу: "давай лучше что-то на Python, а не на
Node". Уточнить фреймворк и вид клиента.»

**Ответ пользователя (диалог):**
- Бэкенд: **FastAPI** (рекомендован агентом — современный стандарт, OpenAPI
  на `/docs`, валидация Pydantic);
- Клиент: **Веб-SPA на чистом JS** без Node и сборки — FastAPI раздаёт
  статику, клиент работает с REST API по Bearer-токенам.

---

## 3. Проектирование API и модели данных

**Запрос агенту:** «Спроектируй REST API: эндпоинты, форматы, коды ошибок,
модель БД, систему баллов и уровней, схему авторизации».

**Результат:**
- Единый формат ошибок `{error: {code, message, details}}`;
- Таблицы: users, events, participants, refresh_tokens;
- Все даты — строки ISO 8601 UTC (нет проблем таймзон в SQLite);
- Уровни: `level = 1 + ⌊√(points/100)⌋`; звания от «Новичка» до «Хранителя
  планеты»;
- JWT access (15 мин) + refresh (30 дней) с ротацией и детектом повторного
  использования.

---

## 4. Реализация сервера

**Запрос агенту:** «Реализуй сервер на FastAPI + SQLAlchemy 2.0 + SQLite:
модели, схемы Pydantic, сервисы бизнес-логики, роутеры, обработчики ошибок,
rate limiting, security-заголовки, seed демо-данных».

**Результат:** пакет `src/` (~15 модулей): `main.py` (сборка приложения,
CSP, CORS, статика), `models.py`, `schemas.py`, `security.py` (bcrypt + PyJWT),
`services/auth_service.py` и `services/event_service.py`, роутеры auth/me/
users/events/misc, `seed.py` (8 пользователей, 12 мероприятий, 28 записей).

---

## 5. Тесты

**Запрос агенту:** «Покрой API тестами: pytest + httpx TestClient,
in-memory SQLite на каждый тест, без затрагивания файловой БД».

**Результат:** 35 тестов в `tests/` (auth: регистрация/вход/валидация/
ротация/reuse-detection/logout/profile; events: CRUD, права, запись, отмена,
вместимость, завершённые события, подтверждение и баллы «ровно один раз»;
misc: рейтинг, статистика, профили, история участия, health).

Найденные и исправленные баги зафиксированы в `.agent/errors.md`.

---

## 6. Реализация клиента (SPA)

**Запрос агенту:** «Сделай SPA на vanilla JS: hash-роутер, fetch-клиент с
авто-обновлением access-токена, страницы (главная, лента с фильтрами,
детали события, форма создания/редактирования, рейтинг, профиль, вход,
регистрация), светлая/тёмная тема. Визуализации — по методу: KPI-тайлы,
рейтинговые бары одним оттенком, метры; палитра должна пройти валидатор
CVD/контраста».

**Результат:** `src/static/` — index.html, 3 CSS-файла (токены/база/
компоненты), 13 JS-модулей. Палитра типов событий прогнана через
валидатор: подобраны шаги, проходящие все проверки в обеих темах.

## 7. Демо-артефакты

**Запрос агенту:** «Сними скриншоты работающего приложения и демо-видео
30–60 сек: Playwright на Python, скриншоты в docs/screenshots, видео —
docs/demo.mp4».

**Результат:** 8 скриншотов (главная, лента, детали события, рейтинг,
профиль, вход, форма события, мобильная версия) + demo.mp4 (~32 сек: вход
организатора, подтверждение участия, рейтинг, создание события, профиль).

**Сложности:** CDN Playwright недоступен (ECONNRESET) → использован кэш
браузеров (`executable_path`, версия playwright 1.58.0 под ревизии кэша);
CSP приложения блокирует `add_init_script` → вход в демо-сценариях — через
UI-форму; mp4 собирается ffmpeg из пакета imageio-ffmpeg.
